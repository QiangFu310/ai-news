### 1. OpenAI 的"性能工厂"如何让 ChatGPT 保持快速
OpenAI 介绍其内部基于 Codex 的自动化性能工程系统 Performance Factory，用来在 agentic 开发的高速节奏下找回"人跟不上"的性能回归。

- **Regression Workflow（回归工作流）**：性能告警触发后自动开任务，Agent 调查变慢原因、把结论写进任务、并给出修复方案供工程师评审；部署后另一个 Agent 复核指标是否回到基线。三个月多一点的时间里，该工作流完成 **1,700 多次调查、根因定位 600 多例，约合每天 17 次自动调查**。

6. 支持在开启 OpenTelemetry 事件与指标的情况下启用 Code Mode：脚本中的每次工具调用都会发事件；开启 tracing 时仍保持关闭。
7. [VS Code] 拒绝信任提示后，消息框上方新增一行提示，可点 Review trust 在不重载窗口的情况下重新唤起对话框。

**【Changed · 变更（22 项）】**
1. macOS 上的 computer use 采用更新的安全规则，部分动作被拒绝、部分应用权限收窄。
2. 已保存的定时任务：在新建的已登录会话里，早期版本保存的多数任务需要重新排期，但对它们自己会话的 `--resume` 仍会执行。
3. 多数模型上不带目标的 `/code-review` 改为"整条分支对比默认分支"，并修复多提交分支上丢失 diff 的问题。
4. auto 模式降低 `git status` 的调用频率，让大仓库中的多数请求等待更短；可能丢弃改动的 git 命令会被拦到工作树检查完成为止。
5. `/code-review <PR 号> --fix` 与传入 PR URL 时，若 `gh pr diff` 被拒或失败则直接停止，不再"空跑"一轮评审。
6. "Exit and stop tasks"改为结束本会话的定时任务，使其在 resume 后不再运行（若退出时 Claude 仍在响应则例外）。
7. 部分 teammate 面板改用 `/bin/sh` 启动，因此可能不读取 shell 启动文件。
8. macOS 上 computer use 对 30 秒内未完成启动的应用放弃尝试。
9. Gateway：`access_control.allow_cidrs` 为空时的启动警告改为每次启动都给出提示，并在文本日志中加框强调——永远不要把这套网关暴露到公网。
10. 自托管运行器：同一 owner/name 的第二个主机名 clone 改放到基础目录的 `_repos/clones/<host>/` 下，已有 clone 不迁移。
11. 自托管运行器：地址路径含特殊字符的仓库会在新目录重新 clone；指向旧目录的规则与卷不再生效，旧 clone 保留。
12. 自托管运行器：`--repository-folder` 在 `--capacity 1` 下可接受基础目录内的多数文件夹（大于 1 时此类路径会导致启动失败）；与另一仓库会话重叠会被拒绝。
13. Code Mode：PreToolUse hook 报错不再像 Code Mode 之外那样拒绝脚本的工具调用；需要强拒时在 command / HTTP / MCP tool hook 上设 `"onFailure": "block"`。
14. Code Mode：拒绝脚本读取超过 256 MiB 的行区间（此前可能吃掉数 GB 内存），并修复超长行读取超时。
15. Code Mode：在关闭遥测、非必要流量或功能开关时也会启动；管理员可在托管设置里保持关闭。
16. Code Mode：允许运行自己声明 `log`、`preview` 或 `sleep` 的脚本（此前会被拒绝）。
17. macOS 登录续期改用"Claude Code 写入检查"项来测试钥匙串。
18. `/tasks` 标题与页脚的后台计数合并为一个数字，涵盖 shell、监控、MCP 调用、agent、workflow 与定时任务。
19. Stop / SubagentStop hooks 在 `background_tasks` 中把 Monitor 的脚本标为 `monitor` 而非 `shell`。
20. 移除 2.1.326 新增的"按 max_tokens 错误所述上限自动重试"；若网关侧模型输出上限更低，请把 `CLAUDE_CODE_MAX_OUTPUT_TOKENS` 设为该上限。

### Claude Code 2.1.328（2026-11-19）

> 2.1.328 已在 11-19 日报的窗口内详述（Added 14 项、Changed 20 项、Improvements 19 项、Bug Fixes 91 项），此处仅列与使用最相关的要点，避免同一版本在两期报告中重复展开。
